How it works

One request, five guarded stages

Every stage is deterministic except the first — and the first is treated as untrusted input. Nothing reaches the response that the replay validator has not re-simulated from scratch.

01 · schema

Pydantic schema guard

Malformed or structurally invalid requests are rejected with 400 before any LLM call.

02 · LLM

LLM interpreter

One batched structured-output call turns each operator note into a machine-checkable directive.

03 · guardrails

Guardrail validator

Pure-Python checks; near-misses salvaged conservatively, everything else demoted to a safe no_op.

04 · LP

LP optimizer (HiGHS)

Continuous LP over 5 variables × 24 hours — energy balance, battery limits, directives, end-of-day neutrality.

05 · replay

Replay validator

Independent judge-mirror re-simulation; totals are recomputed from hourly_plan, never trusted.

Untrusted by design

The LLM proposes; guardrails dispose

The language model is the only source of directives and is never trusted. Its output is data, not logic — malformed suggestions can never crash the service or invent a constraint.

✓Salvage, don't discard

Numeric strings coerced, unsorted hours re-sorted, index forced positional — near-misses are repaired deterministically before rejection is considered.

✓Safe demotion

Anything that fails validation becomes a no_op with an explanation. The schedule stays valid; nothing is invented.

✓Provider-outage proof

Bounded retries with backoff; on sustained failure the request short-circuits to safe interpretations and still returns a valid schedule.

§Closed directive taxonomy

Six directive types, exact adjustment shapes, hours unique/ascending/0–23, factor ∈ [0,1], non-negative finite numerics.

§Independent replay

A separate judge-mirror module re-simulates the returned plan at 0.01 tolerance and blocks the response on any rule failure.

§No secret leakage

Errors are generic and controlled — no stack traces, no config, no provider details in any response body.

Quality gates

Judge-side acceptance, not just unit tests

Every response is validated against a strict JSON Schema and independently replayed against the organizer ground truth.

✓165 tests, ~3 s

Every guardrail rejection path, LP unit tests with hand-verified optima, and all 10 public samples end-to-end.

✓Adversarial notes

50 hidden-style paraphrases across all six directive types scored through the full interpretation path — usable as a release gate.

✓Negative schema controls

Broken responses (extra fields, wrong shapes, out-of-range hours) are proven rejected, not merely untested.
